Primer incremento de la recomendación REDUCIR PCN · 7 de octubre de 2026

SIMULADO, no productivo. Captura ficticia → emisor → wallet → servicios A y B. Sin KYC humano real, aceptación jurídica, proveedores remotos ni conformidad OpenID/SD-JWT. No se modificó producción.

Qué hace la demostración

  1. Inyecta un documento, una selfie y datos personales ficticios en el proveedor.
  2. Emite dos constancias JWS distintas, vinculadas a claves holder y audiencias diferentes. Solo afirma mayoría de edad y KYC vigente.
  3. Ambos servicios comprueban firma, emisor, expiración, clave holder, nonce, contexto y política.
  4. Guarda recibos transaccionales y recupera la decisión cuando se pierde la respuesta.
  5. Audita archivos, logs, cache, backups y una restauración controlada buscando los marcadores documentales.

Resultado observado

PASS: 21 controles JWS; 18 archivos auditados. Los marcadores estaban en la evidencia y backup del proveedor, y no en los archivos controlados de la wallet ni de A/B. Los dos servicios recuperaron el recibo tras la pérdida de respuesta y tras restore.

La ausencia de marcadores es una observación limitada. La versión 0.2 añade búsqueda acotada en Base64/Base64URL/JWT; no cubre otras transformaciones, tráfico, memoria, crash dumps, soporte externo ni software ajeno. El proveedor sabe que las dos constancias pertenecen a la misma persona.

El control de clave comprometida observa una falsificación aceptada antes del retiro del emisor. No demuestra resistencia a robo de clave. La recuperación de autoridad de la referencia es una fixture en memoria; la wallet usa claves efímeras.

Actualización 0.2: estados y observabilidad

El laboratorio suma perfiles simulados de Ripio, Sumsub, Truora y Veriff, consulta por autorización y logs mínimos. La auditoría busca también canarios en Base64, Base64URL y segmentos JWT. Sigue sin conectar proveedores reales ni certificar sus APIs. El experimento de estados es independiente del flujo wallet/JWS.

Ejecutar python demo_proveedores.py y python -m unittest discover -v. Consultar README y contratos, fuentes y límites. La matriz de abajo conserva las responsabilidades propuestas, pendientes de aprobación por un integrador.

Cómo ejecutarla

En una carpeta de laboratorio con Python 3.11 o 3.12; esta actualización se ejecutó en Linux con 3.12:

python -m venv .venv
# Activar .venv según el sistema operativo.
python -m pip install -r requirements.txt
python demo_minimizacion.py

Produce resultado_minimizacion.json. Los archivos inspeccionados y las claves de la fixture son temporales; el resultado conserva rutas, tamaños, hashes y detecciones, no las claves privadas.

Primer bloqueo para una prueba real

Nombrar un integrador, acordar qué información necesita para su función y obligación, quién conserva la evidencia y cómo puede obtenerla. Después medir el flujo convencional contra esta reducción. No hay base para eliminar documentos legalmente exigidos ni para prometer anonimato total.

JWS estándar con claims privados de laboratorio; no SD-JWT ni OID4VCI/OID4VP interoperable. Comparación de tres ubicaciones documentales frente a una: modelo sintético, no benchmark comercial.
